## Описание

Аудит и трассируемость действий ИИ-агентов: каждый агентский шаг (запрос, retrieval, tool call, скомпилированный контекст) фиксируется с уникальным trace-id, бюджетом, таймаутом и результатом. Аудит-след — основа проверки принципа «агент готовит — человек подтверждает и отвечает» и контроля безопасности (что агент делал, с каким бюджетом, какой результат вернул).

## Критерии приёмки

- Каждый агентский шаг имеет уникальный trace-id и фиксируется в журнале: агент, действие, время, бюджет, результат
- Доля агентских шагов с полным аудит-следом — 100% (целевое значение; мера — число шагов с полным следом / все шаги за период)
- Состав «полного аудит-следа» агентского шага — 10 обязательных полей (решение стейкхолдера 2026-08-30): `timestamp` (ISO 8601 UTC), `agent_id`/`token_id`, `session_id`/`task_id`, `step_type`, `input_artifact_refs` (ID+version), `output_artifact_refs`, `llm_call` (модель, контур, input/output токены, hash промпта/ответа), `result_status`, `human_approver`, `immutability` (append-only + hash-цепочка)
- Срок хранения журнала аудит-следа: **1 неделя** (решение стейкхолдера 2026-08-30; риск-флаг: короче типичного окна обнаружения инцидентов — при ужесточении корпоративной политики пересмотреть)
- Отказы, ограничение темпа и превышение бюджетов фиксируются с причиной
- Поддерживаются точки подтверждения человеком для рискованных операций (A3) — подтверждение/отклонение фиксируется в аудит-следе
- Аудит-след воспроизводим по trace-id: по ID шага восстанавливаются входы, решения и выходы
- Запись считается **достаточным доказательством** для расследования при выполнении двух условий: все 10 обязательных полей присутствуют и заполнены корректно; аудит-след воспроизводим по `trace-id` (восстанавливаются входы, решения и выходы)
