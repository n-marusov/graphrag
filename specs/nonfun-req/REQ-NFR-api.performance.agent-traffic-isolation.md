## Описание

Изоляция агентских всплесковых нагрузок (многократные циклы извлечения, сборка контекста, вызовы инструментов, итерации и уточнения) от интерактивных запросов. Агентские запросы подчинены квотам, бюджетам, таймаутам и приоритизации; интерактивные запросы имеют приоритет, чтобы агенты не «съедали» отзывчивость системы и не блокировали переиндексацию.

## Критерии приёмки

- Burst-нагрузка агентов (в рамках стартовых квот: RPS ≤ 10/агент, бюджет токенов ≤ 50k/запрос) не деградирует медиану и p90 интерактивных запросов сверх **p50 ≤ ×1.5 от простоя**; абсолютный потолок — **p90 ≤ 10 с** (бюджет `query-responsiveness`; решение стейкхолдера 2026-08-30, подтверждается нагрузочным тестом Фаза 1.5 и калибруется по телеметрии)
- Каждый агентский запрос подчинён квоте/бюджету — **стартовые консервативные значения** (калибровка по телеметрии, ADR agent-gateway-scheduling-layer): бюджет токенов ≤ 50k токенов/запрос, ≤ 20 шагов извлечения, ≤ 10 вызовов инструментов; таймаут шага ≤ 30 с, таймаут workflow ≤ 10 мин; RPS агента ≤ 10 (стартовое)
- Превышение бюджета/квоты/таймаута → `429`/backoff с фиксацией причины (UC-mcp A2); интерактивные запросы приоритетнее агентских в планировании
- Долгие/тяжёлые агентские шаги выполняются асинхронно и не блокируют интерактивный путь
- Агентские workflow не блокируют публикацию новых версий индекса (не конфликтуют с переиндексацией)
- Промпт-инъекция через содержимое корпуса («игнорируй предыдущие инструкции»): детекция, блокировка, `SecurityEventEmitted` (UC-mcp A3); алгоритм детекции — правила + LLM-классификатор (реализация)

**Метод валидации (нагрузочный тест, решение владельца 2026-08-30):**

- **Профиль нагрузки** — эмуляция пиковой активности нескольких агентов одновременно: RPS ≤ 10/агент; бюджет токенов ≤ 50k/запрос; ≤ 10 tool calls/запрос; workflow ≤ 10 мин (проверяется корректное принудительное завершение по таймауту; долгие задачи — асинхронно)
- **Пороги теста:** p50 интерактивных запросов ≤ 1.5× от простоя; p90 ≤ 10 с; доля ошибок < 1% (warn — рост HTTP 5xx или `429` сигнализирует о деградации пропускной способности)
- **Среда и моки:** prod-подобный стенд; реалистичные моки LLM и инструментов (не «глупые» заглушки — исключают бесконечные циклы и нереалистично низкую задержку); измерения латентности — на уровне API интерактивных запросов
- **Квоты:** при превышении бюджетов/лимитов агентские запросы корректно завершаются `429`/backoff и не влияют на интерактивный путь
- **Калибровка:** целевые p50/p90 для конкретного корпуса определяются пилотным замером (`REQ-NFR-api.performance.query-responsiveness`) и калибруются по телеметрии
