## Описание

Минимизация токенов и числа LLM-вызовов как сквозное требование: локальные GPU и open-weight модели с ограниченным контекстом; экономия токенов — через онтологический слой, PathRAG, PPR (без LLM на этапе извлечения).

**Механизмы баланса (2026-08-30):** онтологический слой сокращает контекст более чем на 50% без потери точности; пайплайн различает типы запросов (избегает context dilution на фактологических вопросах — стратификация `REQ-NFR-api.compliance.rag-accuracy`); аномально большие контексты (например, юридические документы > 179k токенов) — исключение, допустимо для MVP, оптимизируется онтологией.

## Критерии приёмки

- Полнота контекста при минимуме токенов на эталонных задачах (F3, vision §2.5): доля артефактов, необходимых для задачи, включённых в контекст, при минимальном размере контекста в токенах — **≥ 90%** (доля необходимых артефактов в контексте; целевое значение стейкхолдера 2026-08-30, подтверждается замером исходного уровня, vision §1.4)
- Размер контекста на интерактивный запрос (эталонный набор): **медиана ≤ 4 000 токенов, p90 ≤ 8 000**
- Число LLM-вызовов на запрос: **≤ 2** (медиана), абсолютный лимит **≤ 3** (retrieval без LLM — PPR/PathRAG)
- **Порог сохранения качества:** при соблюдении лимитов точность RAG на эталонном наборе — **≥ 70%** (порог продолжения внедрения, vision §1.4); если точность < 70% при p90 > 8 000 — токен-бюджет увеличивается; если медиана вызовов > 2 — пересматривается маршрутизация запросов
- **Метод измерения (2026-08-30):** прогон эталонного набора K1/K4/K5/K17; замер медианы и p90 размера контекста на запрос; оценка точности — LLM-as-a-Judge (логическая корректность, предпочтительнее BERTScore); калибровка целевых значений — пилотным замером Фазы 1.5 (vision §2.6)
