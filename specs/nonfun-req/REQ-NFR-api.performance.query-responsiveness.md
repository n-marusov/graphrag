## Описание

Отзывчивость запросов при фоновой переиндексации: инкрементальные обновления, полные перестройки и фоновые пересчёты не блокируют и не деградируют путь интерактивных запросов. Запросы обслуживаются из последней опубликованной (стабильной) версии индекса без ожидания завершения перестройки.

## Критерии приёмки

- Медиана и p90 времени ответа (G1) при активной фоновой переиндексации не деградируют относительно простоя сверх допустимого порога — **p50 ≤ 5 с, p90 ≤ 10 с** (E2E, интерактивные запросы с grounding; целевые значения стейкхолдера 2026-08-30, подтверждаются замером исходного уровня, vision §1.4 G1)
- Порог деградации при фоновой переиндексации: **p50 ≤ ×1.5 от простоя**, абсолютный потолок — p90 ≤ 10 с (обоснование достижимости: H200, 141 ГБ; 70B open-weight Q4 — prefill ~2–4k ток/с, decode ~60–120 ток/с; типовой запрос 2k контекст / 300 токенов ответа ≈ 3.5–5 с, тяжёлый 8k / 500 ≈ 7–9 с)
- Во время переиндексации запросы обслуживаются из последней опубликованной версии индекса, без ожидания завершения перестройки
- Ни один запрос не наблюдает «полусобранное» состояние индекса (атомарная публикация)
- Запросы пользователя имеют приоритет над фоновыми задачами переиндексации
