## Описание

Актуальность базы знаний: изменение источника (MR в GitLab, событие или периодическая сверка внешнего хранилища документов) актуализирует индекс без полной перестройки. Пересчитываются только затронутые части (чанки, сущности, связи, локальные суммаризации); полная перестройка — периодическая фоновая санация, а не реакция на каждое изменение.

**Подтверждённые механизмы (2026-08-30):** обнаружение изменений — событийный триггер (латентность обработки < 1 с) + polling-фолбэк с интервалом ~5 мин; избирательный пересчёт затронутого подграфа; кэширование LLM-извлечений по хешам (неизменные документы не пересчитываются). Замечание: добавление контента может менять структуру сообществ, требуя пересчёта большей части индекса — подтверждает необходимость фоновой полной перестройки (A7).

## Критерии приёмки

- Время от изменения источника (MR / событие хранилища) до публикации обновлённого индекса — **целевые значения (2026-08-30): медиана ≤ 5 мин, p90 ≤ 15 мин** (инкрементальное обновление затронутого подграфа). Обоснование: практика инкрементальных обновлений GraphRAG/LightRAG — минуты для точечных изменений; событийный режим — субсекундная обработка; референс 281 мин на 1 млн токенов на CPU (ADR-DES.INFRA.container-composition) относится к **полной перестройке** (фоновая операция, вне горячего пути запросов) и к инкрементальному обновлению неприменим. Готовых цифр по пилоту нет — значения подтверждаются целевым замером (Фаза 1.5)
- Цели 5/15 мин **подтверждаются пилотным замером Фаза 1.5** (план подтверждён владельцем продукта 2026-08-30): корпус ~1k артефактов из реальных MR, 10–20 событий с 1–50 изменёнными документами, замер «событие → публикация»; критерий — медиана ≤ 5 мин, p90 ≤ 15 мин; выбросы (крупные MR) фиксируются, при необходимости вводится механизм отложенной публикации; результаты документируются для стейкхолдера
- Доля ответов, опирающихся на актуальные версии источников, — **целевая ≥ 95%** (G2; подтверждается замером)
- При изменении одного документа пересчитывается только затронутое подмножество индекса (затронутый подграф), а не весь индекс (vision §3.2: полная перестройка на каждое изменение недопустима)
- Полная перестройка выполняется как фоновая операция и не попадает в горячий путь запросов (A7)
