# ADR-IMPL.OPS.monitoring-grafana — Панели мониторинга: self-hosted Grafana

| Поле | Значение |
|------|----------|
| **Статус** | ПРИНЯТО |
| **Дата** | 2026-08-30 |
| **Контекст** | Метрики публикуются в контейнер «Мониторинг и аудит» (C4) и потребляются корпоративным мониторингом/панелями ИБ (`REQ-NFR-api.observability.golden-signals`); инструмент панелей не был зафиксирован. Решение владельца продукта (2026-08-30): статусы и метрики вне GUI — в панели мониторинга (Grafana). |
| **Требование-источник** | Решение владельца продукта (2026-08-30); `REQ-NFR-api.observability.golden-signals`; `ADR-DES.INFRA.container-composition` (контейнер «Мониторинг и аудит»); `ADR-DES.UI.chat-only-interface` (метрики вне GUI) |

## Решение

Панели мониторинга и аудита контейнера «Мониторинг и аудит» — **self-hosted Grafana** (внутри периметра, open-source — `BR-constraint.opensource-only`).

- **Данные:** метрики и алерты golden-signals (`REQ-NFR-api.observability.golden-signals`), события безопасности `SecurityEventEmitted`; дашборды — статусы индексации (F2), латентность ответа p50/p90, точность RAG, число противоречий, покрытие связей артефактов (glossary §8).
- **Периметр:** Grafana разворачивается внутри периметра; данные не покидают периметр (NFR-SEC-1).
- **Точка входа:** ссылка «Мониторинг» в футере UI (`BR-constraint.ui-footer`) ведёт на панель Grafana.
- **Доступ:** для эксплуатации и ИБ (панели журналов, vision.md §3.1); детали доступа и состав дашбордов — `specs/open-questions.md`, Блок 4.

## Рассмотренные альтернативы

- **Внешний корпоративный мониторинг (SaaS)** — отклонено: данные не покидают периметр (`ADR-DES.INFRA.container-composition`: вариант «Мониторинг и аудит — внешняя система» отклонён).
- **Собственные панели в UI** — отклонено в `ADR-DES.UI.chat-only-interface`.

## Последствия

**Положительные:**
- Стандартный инструмент индустрии; дашборды по golden-signals без самописных панелей.
- Метрики (p50/p90, точность RAG) доступны эксплуатации без расширения UI.

**Отрицательные и смягчение:**
- Дополнительный компонент стека (контейнер, обновления, бэкапы) → включается в compose-контур MVP (`ADR-DES.INFRA.container-composition`).
- Grafana — дополнительная поверхность атаки → во внутренней сети за гейтвеем, аутентификация через SSO (Keycloak, `ADR-DES.SECURITY.sso-keycloak`).
- Дашборды и права доступа не определены → фиксируются в open-questions до реализации.

## Критерии пересмотра

- Появление корпоративного стандарта мониторинга, конфликтующего с Grafana.
- Рост требований аудита за пределы возможностей Grafana (пересмотр стека).
