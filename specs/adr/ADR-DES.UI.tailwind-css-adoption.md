## Решение

Стилизация фронтенда — **Tailwind CSS v4** (актуальная мажорная версия на дату решения), подключаемый официальным Vite-плагином (`@tailwindcss/vite`) без отдельной PostCSS-конфигурации.

- **Конфигурация — CSS-first:** дизайн-токены объявляются в CSS через `@theme` (переменные CSS), кастомные стили — через `@layer`; отдельный `tailwind.config.js` не вводится без необходимости.
- **Дизайн-система:** токены (цвета, типографика, отступы, радиусы, тени) + утилиты Tailwind; тёмная тема по умолчанию (инструмент для команд разработки); повторяющиеся комбинации выносятся в компоненты Vue SFC и `@apply`.
- **Без UI-китов:** тяжёлые библиотеки компонентов не используются — стилизация на токенах и утилитах (принцип тонкого SPA, `ADR-DES.UI.spa-typescript-frontend`).
- **Доступность:** WCAG 2.1 AA обеспечивается токенами (контраст, focus-visible) и семантической разметкой; в продакшене Tailwind не создаёт рантайм-инъекций стилей (совместимость с CSP).
- **Версия:** закрепляется в `package.json`; обновления мажорных версий — планово, с проверкой миграции.

## Рассмотренные альтернативы

- **Tailwind CSS v3** — предыдущая мажорная версия: JS-конфигурация и ручная настройка; на дату решения актуальный стандарт индустрии — v4.
- **Vanilla CSS + CSS-переменные** — ручная дизайн-система без утилит: больше дублирования и ниже предсказуемость ИИ-генерации.
- **CSS Modules** — локальная изоляция стилей, но нет дизайн-токенов и темизации из коробки; разнородность при росте.
- **CSS-in-JS (styled-components, vanilla-extract)** — дополнительные зависимости и этапы сборки без выгоды для SPA без SSR.
- **UI-киты (Naive UI, PrimeVue и т. п.)** — тяжёлые, навязывают дизайн, конфликтуют с кастомной дизайн-системой и тонким клиентом.

## Последствия

**Положительные:**
- Единый предсказуемый язык стилей; ИИ-генерация кода на Vue 3 + Tailwind — зрелая практика индустрии (принцип «код генерируется ИИ-агентами и проверяется человеком»).
- Дизайн-токены как CSS-переменные (`@theme`) — тёмная/светлая темы, контраст WCAG AA, стили не привязаны к локали (i18n).
- Малый вес: Tailwind v4 компилирует только используемые классы (Lightning CSS), без рантайм-зависимостей.
- CSS-first конфигурация упрощает онбординг и ревью (нет JS-конфига стилей).

**Отрицательные и смягчение:**
- Утилитарные классы в разметке повышают связность с дизайном → повторяющиеся паттерны выносятся в компоненты и токены, хардкод значений запрещён.
- Риск «эрозии классов» в больших компонентах → ревью и выделение комбинаций в `@apply`/компоненты.
- Мажорные обновления Tailwind могут требовать миграции → версия фиксируется в `package.json`; обновление — плановое, с проверкой совместимости и подтверждением.

## Критерии пересмотра

- Появление корпоративного стандарта стилизации, конфликтующего с Tailwind.
- Невозможность достичь WCAG 2.1 AA на текущих токенах (пересматриваются токены, а не инструмент).
- Мажорная версия Tailwind с несовместимыми изменениями и отсутствием пути миграции.
