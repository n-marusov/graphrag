# ADR-DES.UI.chat-only-interface — Веб-интерфейс: только чат (F1)

| Поле | Значение |
|------|----------|
| **Статус** | ПРИНЯТО |
| **Дата** | 2026-08-30 |
| **Контекст** | Веб-интерфейс (контейнер C4 «Веб-интерфейс (UI)») ранее включал, помимо чата, статусы индексации, метрики и отчёты о влиянии (`ADR-DES.UI.spa-typescript-frontend` — контекст; glossary «Веб-интерфейс (UI)»; `BR-constraint.web-app-browser-chat` — критерий «В UI доступны ответы, статусы индексации и метрики»; `REQ-NFR-api.observability.golden-signals` — «Метрики доступны в UI администратора»). Дизайн-сессия GUI (2026-08-30, Pixso) зафиксировала другое решение: GUI нужен только для вопросов/ответов; статусы, метрики, анализ влияния и компиляция контекста — вне GUI. |
| **Требование-источник** | Решение владельца продукта (2026-08-30, дизайн-сессия GUI); `BR-constraint.web-app-browser-chat` (чат в браузере, WCAG 2.1 AA); `ADR-DES.UI.spa-typescript-frontend` (тонкий SPA) |

## Решение

Веб-интерфейс GraphRAG — **только чат** (F1.1, базовый F1.2): вопрос → проверяемый ответ с grounding и provenance.

- **Состав UI:** история сессий слева, контент чата по центру, панель происхождения справа, шапка (версия индекса, переключатель темы, выбор языка), футер (версия продукта, ссылка «Мониторинг»).
- **Вне GUI:** статусы индексации и метрики — панели контейнера «Мониторинг и аудит» (Grafana, `ADR-IMPL.OPS.monitoring-grafana`); анализ влияния (F3.1) и компиляция контекста (F3.2) — MCP (`UC-mcp.compile.context`, K17) и CLI (`BR-constraint.backend-cli-queries`).
- **Граница:** UI read-only, без write-операций (`BR-constraint.sso-readonly-access`); детали компоновки — BR `ui-session-history`, `ui-header`, `ui-footer`, `ui-visual-standards`.

## Рассмотренные альтернативы

- **UI с панелями статусов/метрик (прежний состав)** — отклонено: статусы и метрики дублируют панели мониторинга; администрирование индексации — вне сценария «разработчик задаёт вопрос».
- **UI с анализом влияния и компиляцией контекста** — отклонено: F3 — контур для ИИ-агентов (MCP) и автоматизации (CLI), не для ручного GUI-сценария.

## Последствия

**Положительные:**
- Тонкий UI с минимальной поверхностью: меньше XSS-поверхности и a11y-работы (`ADR-DES.UI.spa-typescript-frontend` — «тонкий клиент без бизнес-логики»).
- Единый сценарий пользователя (вопрос → ответ) — ниже когнитивная нагрузка, проще E2E GUI (`qa/e2e-gui-testing.md`).

**Отрицательные и смягчение:**
- Изменение состава UI требует актуализации производных артефактов: критерий `BR-constraint.web-app-browser-chat`, пункт `REQ-NFR-api.observability.golden-signals`, определение glossary «Веб-интерфейс (UI)», объекты `qa/e2e-gui-testing.md` §3.2, контейнер UI в `.ai-factory/ARCHITECTURE.md` — правки выполняются отдельным изменением.
- Статусы/метрики становятся доступны только через Grafana — требуется доступ эксплуатации к панелям (вопрос доступа — `specs/open-questions.md`, Блок 4).

## Критерии пересмотра

- Потребность команд в статусах индексации/метриках внутри GUI (решение — расширение состава UI новым ADR).
- Невозможность покрыть сценарий анализа влияния через MCP/CLI.
