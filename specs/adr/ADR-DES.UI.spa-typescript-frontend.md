## Решение

Фронтенд — **тонкий SPA на TypeScript**, разворачиваемый в браузере пользователя, вне серверной кодовой базы Go.

- **Язык:** TypeScript (строгая типизация, стандарт индустрии 2026, зрелая экосистема ИИ-генерации кода — согласуется с принципом «код генерируется ИИ-агентами и проверяется человеком»).
- **Фреймворк:** Vue 3 (Composition API) — решение владельца продукта (2026-08-30; кандидат — React — отклонён в пользу Vue 3 как «стандартного и привычного», с русскоязычной экосистемой). Фиксация выбора здесь делает решение явным и пересматриваемым.
- **Сборка:** Vite; клиент генерируется из OpenAPI 3.1-схемы API (контрактный подход, spec-driven).
- **Границы:** фронтенд — только чтение и представление; никаких write-операций и бизнес-логики на клиенте (read-only, `BR-constraint.sso-readonly-access`); доступ — через API Gateway (OIDC-токен SSO, `ADR-DES.SECURITY.sso-keycloak`).
- **Качество:** WCAG 2.1 AA (`BR-constraint.web-app-browser-chat`); локализация русский/английский с i18n-архитектурой (возможность добавления локалей).

## Рассмотренные альтернативы

- **Go-шаблоны / go:embed статики в гейтвее** — отклонено в `ADR-DES.API.api-gateway-adoption` (только временный компромисс MVP; статика — отдельный слой).
- **React** — отклонён (см. выше).
- **Svelte / vanilla TS** — не рассматривались как основные (меньше стандартность/экосистема для корпоративного SPA).

## Последствия

**Положительные:**
- Независимый жизненный цикл фронта (уже зафиксирован в API Gateway ADR): контрактные тесты на кэш-заголовки и SPA-fallback.
- Чёткая граница Go (сервер) / TS (клиент) упрощает ИИ-генерацию: контракт — OpenAPI 3.1, типы клиента генерируются.
- Стандартный стек 2026 года снижает стоимость онбординга.

**Отрицательные и смягчение:**
- Два тулчейна (Go, Node) в репозитории → CI включает отдельную сборку фронта; контрактные тесты фиксируют несовместимости до деплоя.
- Фронтенд — дополнительная поверхность атаки (XSS) → CSP-заголовки на статик-сервере, отсутствие опасных шаблонов; проверки — в E2E GUI (негативные и security-сценарии, `qa/e2e-gui-testing.md`).
- Риск дрейфа клиента от API → генерация клиента из OpenAPI-схемы в CI.

## Критерии пересмотра

- Потребность в SSR/индексируемости (не требуется для внутреннего инструмента) — пересмотр не требуется без нового требования.
- Рост фронтенда до состояния, когда Vite-сборка не укладывается в стандартный CI-пайплайн — пересмотр инструментов сборки.
