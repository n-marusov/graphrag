## Формулировка правила

Веб-интерфейс (чат GraphRAG) ведёт **историю сессий**: левая панель — список сессий (первый вопрос сессии, дата и время), активная сессия подсвечена; доступны «+ Новая сессия», переименование, удаление и поиск по сессиям. История хранится **на сервере** (не в localStorage): список сессий доступен после перезагрузки страницы и с другого устройства.

## Обоснование

UI — только чат (`ADR-DES.UI.chat-only-interface`); повторные обращения к системе знаний — через сессии. Серверное хранение согласуется с тонким клиентом без бизнес-логики (`ADR-DES.UI.spa-typescript-frontend`) и read-only-границей доступа (`BR-constraint.sso-readonly-access`). История сессий не зафиксирована в vision.md — правило закрывает лакуну.

## Критерии проверки

- Список сессий отображается в левой панели после перезагрузки страницы (данные — из API через API Gateway)
- «+ Новая сессия» создаёт сессию и переводит чат в пустой диалог
- Переименование, удаление и поиск по сессиям работают; активная сессия визуально выделена
- Никакие данные истории не хранятся в localStorage
