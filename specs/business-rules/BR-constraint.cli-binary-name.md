## Формулировка правила

Имя исполняемого файла (бинарника) CLI продукта — **`graphrag`** (на Windows — `graphrag.exe` по конвенции платформы). Имя фиксировано и не содержит версии, суффиксов или дополнительных расширений: скрипты, CI и тестовые прогоны обращаются к бинарнику как к команде `graphrag`.

## Обоснование

Бинарник CLI — интерфейс для скриптовой автоматизации, CI и тестовых прогонов (`BR-constraint.backend-cli-queries`: CLI необходим «для прогона тестовых запросов и скриптовой автоматизации без графического интерфейса»). Стабильное имя из одного слова делает команды детерминированными (smoke: `graphrag --version`, SM-D-10) и исключает расхождения между документацией, сборкой и стендами. В Go-кодовой базе точке входа соответствует каталог `src/cmd/graphrag` (целевое состояние).

## Критерии проверки

- После сборки продукта существует исполняемый файл с именем `graphrag` (`graphrag.exe` на Windows)
- `graphrag --version` возвращает версию продукта (SM-D-10); `graphrag --help` доступен
- В документации, скриптах и CI имя бинарника используется без вариантов (`graphrag`, а не `graphrag-cli`, `graphragvX` и т.п.)
