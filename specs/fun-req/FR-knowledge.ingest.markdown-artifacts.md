## Описание

Корпус знаний потребляет markdown-артефакты целевого проекта из GitLab: спецификации, требования, бизнес-правила, архитектурные документы и прочую документацию в формате markdown (тип T1 перечня). Обработка в F2: загрузка → чанкинг → LLM-извлечение сущностей, связей и утверждений → инкрементальное обновление графа знаний.

## Критерии приёмки

- Markdown-файлы из разрешённых путей GitLab-репозитория попадают в корпус: содержимое чанкуется, сущности/связи/утверждения извлекаются с привязкой к чанкам (`DocumentIngested → EntityExtracted`)
- Изменение/удаление markdown-файла (MR merged / push) инкрементально актуализирует индекс без полной перестройки (REQ-NFR-data.performance.index-freshness)
- Файлы форматов вне перечня T1–T5 пропускаются с WARN и в корпус не включаются (A3, UC-knowledge.sync.gitlab-index)
