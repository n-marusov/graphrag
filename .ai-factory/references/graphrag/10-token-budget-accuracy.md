# Баланс токен-бюджета и точности RAG: ориентиры

> **Источник:** результаты веб-поиска владельца продукта (2026-08-30) — данные по токен-бюджетам и точности GraphRAG/OWL-подходов; атрибуция по пунктам TBD (URL источников не зафиксированы в сводке)
> **Создано:** 2026-08-30
> **Назначение:** обоснование лимитов `REQ-NFR-api.performance.token-minimization` (p90 ≤ 8 000 токенов, вызовы ≤ 2/≤ 3) при сохранении точности ≥ 70%

## Обзор

Баланс между размером контекста, числом LLM-вызовов и точностью — ключевой для локального контура (open-weight модели, ограниченный контекст). Внешние ориентиры показывают, что структура контекста важнее его объёма, а жёсткий токен-бюджет достижим без потери точности при использовании онтологического слоя и retrieval без LLM.

## Ориентиры точности и токенов

- **Не-OWL GraphRAG** (базовый подход без онтологии): точность до **89.9%** с GPT-4o.
- **Средний контекст (Avg-Ctx)** GraphRAG на сложных датасетах: **8–37 тыс. токенов** на запрос — требование продукта (p90 ≤ 8 000) жёстче; достижимо с онтологическим слоем и PPR-методами (retrieval без LLM).
- **Онтологический слой (TBox)**: сокращает токены **более чем на 50%** без потери точности; OWL-контексты позволяют слабым LLM достигать точности до **88%**.
- **Context dilution**: GraphRAG может терять точность на прямых фактологических вопросах при раздувании контекста — пайплайн должен различать типы запросов.
- **Аномалии**: юридические документы могут давать контекст **> 179 тыс. токенов** — исключение; для MVP допустимо, требует оптимизации онтологией.

## Применение в продукте

- Лимиты (решение владельца продукта 2026-08-30): размер контекста на запрос — медиана ≤ 4 000, p90 ≤ 8 000 токенов; число LLM-вызовов — ≤ 2 (медиана), ≤ 3 (абсолютный лимит); точность RAG ≥ 70% сохраняется при соблюдении лимитов (`REQ-NFR-api.performance.token-minimization`).
- Метод измерения: прогон эталонного набора K1/K4/K5/K17; замер медианы/p90 размера контекста; оценка точности LLM-as-a-Judge (логическая корректность, предпочтительнее BERTScore); правила коррекции: точность < 70% при p90 > 8k → увеличить токен-бюджет; медиана вызовов > 2 → пересмотреть маршрутизацию запросов.
- Калибровка целевых значений — по пилотному замеру Фазы 1.5 (vision §2.6).
