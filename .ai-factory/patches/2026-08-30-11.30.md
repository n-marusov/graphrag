# Mermaid flowchart does not render: unquoted labels with non-ASCII symbols

**Date:** 2026-08-30 11:30
**Files:** specs/c4/code-query-behavior.md, specs/c4/code-indexing-pipeline.md
**Severity:** medium

## Problem

The `Поведение движка запросов` mermaid flowchart (`specs/c4/code-query-behavior.md`)
did not render in the editor. Diagnosis: the mermaid lexer in older renderer versions
(v9-class) throws `Lexical error on line N. Unrecognized text.` when a node/edge label
contains non-ASCII symbol characters (en-dash `–` U+2013, arrows `→` U+2192 / `↔` U+2194,
guillemets `«»`) in an **unquoted** label.

Verified by installing mermaid v9 / v10 / v11 in a temp dir and running `mermaid.parse()`:

| Diagram state | v9 | v10 | v11 |
|---|---|---|---|
| unquoted labels + unicode symbols | FAIL | OK | OK |
| quoted labels + unicode symbols | OK | OK | OK |

The sibling diagram `specs/c4/code-indexing-pipeline.md` had the same latent bug
(unquoted `600–800` en-dash) and failed identically on v9.

## Root Cause

Mermaid flowchart labels are free text only when they match the lexer's text token
pattern. In older mermaid versions the pattern does not include non-ASCII symbol
characters (dashes, arrows, guillemets, semicolons), so those characters are lexed as
unexpected tokens and the whole diagram fails to parse. Cyrillic letters are fine
(they are word characters); the *symbol* class is the problem. Quoting the label
(`A["text"]`, `-->|"label"| B`) switches the lexer to the STRING token, which accepts
any characters except the closing quote — making the diagram version-independent.

## Solution

Wrapped **all** node labels, edge labels, and shape labels (rectangle, stadium,
diamond, hexagon) in double quotes in both diagrams:

- `Start([Триггер индексации])` → `Start(["Триггер индексации"])`
- `-->|webhook / MR GitLab| Diff[...]` → `-->|"webhook / MR GitLab"| Diff[...]`
- `Check{Сверка «результат ↔ источник» K5}` → `Check{"Сверка «результат ↔ источник» K5"}`

Unicode symbols were kept (safe once quoted). Quotes are mermaid syntax and do not
appear in the rendered text.

## Prevention

- For any mermaid flowchart label containing non-ASCII symbols (`–`, `—`, `→`, `↔`,
  `«»`, `;`, etc.) or special chars (`:`, `/`, `+`, `,`, `(`, `)`), wrap the label in
  double quotes.
- Best practice: quote **all** labels for consistency and future-proofing across
  mermaid versions.
- Before finalizing a diagram, validate with `mermaid.parse()` (npm: `mermaid`,
  needs a DOM shim such as jsdom for `parse()`).
