# Устаревшие диагностики TS-сервера IDE после миграции npm → pnpm

**Date:** 2026-08-31 12:05
**Files:** `src/frontend/package.json`, `src/frontend/tsconfig.app.json`, `src/frontend/tsconfig.node.json`, `src/frontend/src/app/bootstrap.ts`, `src/frontend/src/vite-env.d.ts`, `src/frontend/vite.config.ts`
**Severity:** medium

## Problem

После миграции фронтенда с npm на pnpm IDE Zed показывала ошибочные диагностики, которых не было в CLI:

- `src/app/bootstrap.ts` (6 ошибок): `import.meta` не разрешён, `Property 'env' does not exist on type 'ImportMeta'`
- `src/vite-env.d.ts`: `Cannot find type definition file for 'vite/client'`
- `tsconfig.app.json`: `File '@vue/tsconfig/tsconfig.dom.json' not found`
- `vite.config.ts`: `Cannot find module 'vite'`
- `pnpm-workspace.yaml` + `package.json` ×2: `Unable to load schema ... read ECONNRESET`

При этом CLI-проверки были полностью зелёными: `pnpm typecheck` (vue-tsc), `npx tsc -p tsconfig.app.json`, `npx tsc -p tsconfig.node.json`, `pnpm build`, `pnpm test` (111 passed), `pnpm lint`.

## Root Cause

Два независимых источника:

1. **Устаревший кэш модульного резолвинга TS-сервера IDE.** TS-сервер Zed жил через миграцию `node_modules` (npm layout → pnpm junction layout) и добавление `vite` как прямой зависимости. Сервер закэшировал состояние, когда `@vue/tsconfig`/`vite`/`vite/client` были нерезолвящимися (в pnpm-строгом линкере `vite` сначала не был прямой зависимостью — phantom dependency). Ошибки `Cannot find module`/`not found`/`import.meta` — следствие того, что `extends` в `tsconfig.app.json` не разрешился, и TS упал на дефолтные настройки (CommonJS → `import.meta` запрещён, типы не подгружены).

2. **Сетевые ошибки схемы (ECONNRESET)** — IDE не смогла загрузить JSON-схему со `schemastore.org` в момент проверки. Сайт при этом доступен (HTTP 200 из терминала) — ошибка транзиентная, на стороне IDE, а не кода.

## Solution

- **`touch` tsconfig-файлов** (`tsconfig.json`, `tsconfig.app.json`, `tsconfig.node.json`) вызвал перезагрузку проекта в TS-сервере IDE: 8 из 10 ошибок (`bootstrap.ts`, `vite-env.d.ts`, `tsconfig.app.json`) исчезли сразу. Кода менять не пришлось — проект был корректен.
- Оставшаяся ошибка `vite.config.ts` (`Cannot find module 'vite'`) — закэшированный провал резолвинга модуля `vite` в node-проекте; снимается перезапуском TS-сервера в Zed (reload workspace / restart language server). Сетевые ошибки схем уйдут тем же перезапуском.
- Реальный фикс кода (добавление `vite` в `devDependencies`) был сделан ранее — именно он был первопричиной «нерезолвящегося» `vite` в строгом pnpm-линкере.

## Prevention

- После замены `node_modules` (миграция пакетного менеджера, `rm -rf node_modules && pnpm install`) **перезапускать TS-сервер IDE** (Zed: reload workspace или restart language servers), а не полагаться на диагностики без перезагрузки.
- Не доверять диагностикам IDE как источнику истины при подозрении на устаревшее состояние: проверять CLI (`pnpm typecheck`, `npx tsc -p tsconfig.<app|node>.json`) — CLI пересоздаёт проект с нуля.
- После миграции на pnpm проверить phantom dependencies: любой импортируемый пакет должен быть объявлен в `package.json` (pnpm-строгий линкер не хойстит транзитивные зависимости в корень `node_modules`).
- `touch` tsconfig-файлов — быстрый способ вызвать перезагрузку проекта в TS-сервере без рестарта всей IDE (работает частично — снимает ошибки проекта приложения, но не всегда кэш модулей).
