# AGENTS.md

> Карта проекта для ИИ-агентов. Обновляйте при значительном изменении структуры проекта; секцию «Документация» поддерживает `/aif-docs`.

## Обзор проекта

**GraphRAG** — корпоративная система знаний на базе ontology-grounded GraphRAG: evidence-based context layer / context compiler для ИИ-агентов автоматизации разработки (AI Factory, Hand-off). Продукт отвечает, а не выдаёт документы: каждый ответ проверяем — со ссылками на артефакты и происхождением (grounding, provenance). Проект находится на этапе видения (Фаза 0): кодовой базы ещё нет, спецификации — источник правды.

## Технологический стек

- **Язык программирования:** Go (серверная кодовая база), TypeScript (фронтенд)
- **Фреймворк:** Vue 3 + Vite (тонкий SPA, вне серверной кодовой базы; стилизация — Tailwind CSS v4, `ADR-DES.UI.tailwind-css-adoption`)
- **База данных:** Neo4j Community Edition (self-hosted) — граф + векторный индекс (HNSW) + чанки + версионные снапшоты
- **Хранилище источников:** GitLab (спеки/код/онтология), внешнее S3 (книги/легаси)
- **CI:** GitLab CI (гейт валидации mermaid-диаграмм)
- **Инструменты:** Node.js (валидация mermaid: `mermaid`, `jsdom`)

## Трассируемость артефактов

Карта зависимостей (сверху вниз; нижележащий артефакт зависит от вышележащего):

```
specs/glossary.md      ← единый язык: влияет на ВСЕ артефакты
  ↓
specs/vision.md        ← границы продукта: F1–F4, MVP, roadmap, цели G1–G7
  ↓
UC / US / FR / NFR / domain/   (внешние слои: business-rules/, QA-методология)
  ↓
specs/adr/             ← зависит от domain, BR, FR, NFR
  ↓
specs/c4/              ← зависит от adr/
  ↓
specs/contracts/       ← зависит от domain, FR, BR, NFR, ADR, C4
  ↓
specs/qa/ (тесты)      ← unit · integration · smoke · e2e GUI · e2e API: зависят от FR/NFR/BR/UC/US/контрактов
  ↓
src/                   ← зависит от FR, BR, NFR, ADR, C4, контрактов и тестов (TDD)
  ↓
Antora user/developer guide
```

| Изменяешь | Обязательно проверь и исправь нижележащие | Согласуй вышележащий |
|---|---|---|

| `specs/vision.md` | UC, US, FR, NFR, domain, тесты; при изменении F1–F4/границ — ADR, C4 | — |
| `specs/use-cases/` | US, FR, integration- и E2E-тесты | vision.md (границы функций) |
| `specs/user-stories/` | E2E GUI-тесты | UC |
| `specs/fun-req/` | NFR (перекрёстно), ADR, контракты, тесты всех уровней, код | UC, vision.md |
| `specs/nonfun-req/` | ADR (trade-offs), контракты, unit/integration/E2E API-тесты, код | vision.md (G1–G7, §2.7) |
| `specs/domain/` | ADR, контракты, код | vision.md, glossary.md |
| `specs/adr/` | C4, контракты, код, integration-тесты (новый ADR — через «ЗАМЕНЕНО») | требование-источник (FR/BR/NFR/domain) |
| `specs/c4/` | контракты, код, integration-тесты, developer docs | adr/ |

### Правила процедуры

1. **Вниз — обязательно:** при изменении артефакта пройди по строке таблицы; каждый нижележащий артефакт проверяется и при необходимости исправляется в том же изменении. Непроверенный нижележащий артефакт — дефект трассируемости (гейт `G1-TRACE`).
2. **Вверх — уточняющий вопрос:** если изменение требует правки вышележащего артефакта (новый термин → `specs/glossary.md`, изменение границ → `specs/vision.md`, изменение решения → `specs/adr/`), не редактируй его молча — задай уточняющий вопрос, как именно исправить вышележащий артефакт, и вноси правку только после ответа.
3. **Ссылки — по направлению зависимости:** ссылки в тексте идут от нижележащего артефакта к вышележащему (источнику); вышележащий артефакт не ссылается в своём тексте на нижележащие артефакты и не выводит из них своё содержание.

## Правила для агентов

- Следуй карте зависимостей и правилам трассируемости (раздел «Трассируемость артефактов» выше): вниз — обязательно проверить и исправить нижележащие, вверх — согласовать уточняющим вопросом.
- Не комбинируй зависимые shell-команды в одну строку через `&&` (например, `git checkout main && git pull`). Выполняй их последовательно: сначала `git checkout main`, затем `git pull origin main`.
- Следуй правилам проекта `.ai-factory/RULES.md` и архитектуре `.ai-factory/ARCHITECTURE.md`; спецификации — источник правды.
- Обновляй этот файл при значительном изменении структуры проекта; секцию «Документация» поддерживает `/aif-docs`.
